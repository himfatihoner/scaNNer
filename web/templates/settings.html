{{/* IMPORTANT note on Kali / modern Linux: the "setcap" instructions below WORK on traditional iptables-legacy + loaded kernel modules, but FAIL on Kali rolling because: • iptables 1.8+ uses the nf_tables backend; nft's netlink subsystem still root-checks (CAP_NET_ADMIN is not enough on its own under the current kernel). • /run/xtables.lock is root:root 0600 → a non-root process can't even acquire the iptables mutex. • The nf_tables / nft_nat kernel modules are not autoloaded on most Kali installs, and on-demand module load wants CAP_SYS_MODULE (different cap). Until the systemd install script is wired up, the reliable workaround on Kali is to start the binary under sudo. */}}

⚠ Recommended on Kali rolling: start the scanner with sudo

sudo ./scanner

Why: Kali ships iptables-nft, and the nf_tables netlink path + the /run/xtables.lock file still require real root on the current kernel. Capabilities granted via setcap are detected on the process (CapEff: 0x3000) but the kernel refuses the iptables operations anyway.

Trade-off: data/scanner.db and any loot files will be owned by root. You'll need sudo to delete or move them later. The systemd install script (planned — see ~/.claude/projects/-home-user-my-tools-scaNNer/memory/project_install_systemd.md) will fix this for good by spawning the process with AmbientCapabilities while keeping User=user.

Alternative — setcap (works on iptables-legacy systems only)

Grants CAP_NET_ADMIN + CAP_NET_RAW to the binary. On non-Kali distros where iptables uses the legacy backend AND the netfilter/nat kernel modules are pre-loaded, this is enough — and scanner runs as your normal user instead of root.

sudo setcap cap_net_admin,cap_net_raw+ep ./scanner

Then RESTART scanner — setcap is applied to the binary inode, the already-running process does NOT inherit it. Every go build rewrites the binary and clears the capability, so you'd have to re-run setcap after each rebuild.

Pre-flight check before retrying setcap on Kali:

iptables --version # if it says "nf_tables" → setcap won't work, use sudo sudo modprobe nf_tables nft_nat # load modules first (still won't fix the lock file)

How the killswitch works

scaNNer creates an isolated network namespace (scanner-ns) bridged to the selected interface via a veth pair. All scan subprocesses (nmap, nuclei, wpscan, hydra, etc.) spawn inside this namespace — iptables rules drop any traffic that would escape via another interface. If the pinned interface goes down (e.g. VPN disconnect), the kernel-level DROP rule kicks in and every running scan is aborted.
